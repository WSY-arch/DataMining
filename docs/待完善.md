# 实现成熟度说明

本文档用于区分“学习脚手架”和“正式实验组件”。

## 已可用于正式流程的部分

- 统一 pipeline：每种 measure 先产生 pairwise distance matrix，然后由 k-medoids 进行 clustering。
- Chen/Wang 结果共享同一个 CSV schema。
- 固定 `k = ground-truth classes 的数量`，用于保证 benchmark 可比性。
- 通过 `--seeds` 支持 multi-seed repeated runs。
- `scripts/chen_analyze_results.py` 中支持按 seed 聚合 mean/std。

## 仅用于学习/参考的实现

- `tsclust/measures/similarity_measures.py` 中内置的 DTW 和 MSM 是可读的 reference implementations。它们有助于理解原理和做 smoke tests，但不应作为最终 benchmark claim 的首选 backend。
- `--metric-backend reference` 选项只应当用于调试小数据集。

## 首选正式 backend

- 安装 aeon 后，正式 DTW/MSM 运行使用 `--metric-backend aeon`。
- 如果 aeon 不可用，DTW 可以使用 `--metric-backend tslearn`；MSM 仍需要 aeon 或 reference implementation。
- 如果使用 `--metric-backend auto`，代码会尝试已安装的库，并在失败时 fallback 到 reference implementations。这个选项方便，但不够显式；正式运行应强制指定 intended backend。

## 仍未完成/未来改进

- Chen 的代码中尚未实现 SBD。Wang 应使用共享结果 schema 添加它。
- 原项目中已有 IDK integration，但最终实验需要安装 IDK dependency，并在文档中说明 similarity-to-distance conversion。
- Nemenyi post-hoc 和 CD diagram 尚未完整实现。目前 analyzer 提供 average ranks 和 Friedman test summary。
- 当前 length perturbation 使用 truncate + pad。这种方式简单且易解释，但可以增加 resampling-based length experiment 作为 robustness check。
- 如果不同 backend 混用，runtime comparison 应谨慎解释。正式表格应使用一个明确的 backend setting。

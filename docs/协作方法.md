# Chen-Wang 协作协议

## 共享数据接口

每一种方法都会接收：

```text
X: float array with shape (n_samples, series_length)
y: integer labels used only for evaluation
dataset_meta: dataset name, length, class count, domain
```

除非某个特定鲁棒性检查另有说明，所有方法在计算相似性之前都应对每条时间序列做 z-normalization。

## 共享结果 CSV schema

每次运行都必须为每个 dataset、measure、seed 和 perturbation level 写出一行：

```text
dataset,measure,paradigm,ari,nmi,runtime,seed,perturbation_type,perturbation_level,n_samples,series_length,k
```

必填值：

- `measure`: `ed`, `dtw`, `msm`, `sbd`, or `idk`。
- `paradigm`: `lock-step`, `elastic`, `sliding`, or `distributional`。
- `perturbation_type`: `none`, `noise`, `shift`, or `length`。
- `perturbation_level`: 主 benchmark 使用 `0`；扰动实验使用对应的数值 level。
- `k`: ground-truth 类别数；为了公平比较，将它作为 clustering 的聚类数。

**你们必须对齐的东西**

最重要的是结果格式。你们所有方法最后都必须输出同一种 CSV：

```text
dataset, measure, paradigm, ari, nmi, runtime, seed,
perturbation_type, perturbation_level, n_samples, series_length, k
```

比如：

```text
ECG200, dtw, elastic, 0.42, 0.51, 3.82, 1, none, 0, 200, 96, 2
ECG200, idk, distributional, 0.39, 0.48, 2.14, 1, noise, 0.1, 200, 96, 2
```

你负责 ED / DTW / MSM，Wang 负责 SBD / IDK，但你们不能各自输出不同格式。否则 Week 4 写 Results 的时候会崩。

第二个要对齐的是数据接口。统一成：

```python
X: shape = (n_samples, series_length)
y: shape = (n_samples,)
dataset_meta: {
    "name": ...,
    "length": ...,
    "n_classes": ...,
    "domain": ...
}
```

不管是 aeon 下载的 UCR，还是本地文件读的 UCR，最后都必须变成这个结构。

第三个要对齐的是 distance / similarity matrix。

ED、DTW、MSM、SBD 最后最好都变成：

```python
distance_matrix: shape = (n_samples, n_samples)
```

IDK 比较特殊，因为它输出 similarity/kernel。为了公平，建议你们统一写成：

```python
distance = 1 - similarity
```

然后所有方法都走同一个 `k-medoids`。这要写进 Methodology，不然 marker 可能会问：为什么 IDK 用一种聚类算法，其他方法用另一种？

第四个要对齐的是 `k`。

proposal 是 time-series clustering benchmark，不是自动估计类别数，所以建议：

```text
k = ground-truth number of classes
```

不要每个方法自己调 k。否则结果会不公平。

第五个要对齐的是 random seed。

正式实验建议：

```text
seed = 1, 2, ..., 10
```

每个 dataset + measure 都跑 10 次，然后报告：

```text
ARI mean ± std
NMI mean ± std
runtime mean ± std
```

如果时间不够，至少 smoke test 用 1 个 seed，正式主表用 5 或 10 个 seed。

**报告写作怎么协作**

proposal 里 Week 4 分工是：

- 你：Introduction / Related Work / Methodology
- Wang：Results / Discussion / Conclusion

但 Week 3 就要提前为 Week 4 铺路。

你现在写报告时要围绕这个主线：

```text
不同 similarity measures encode different invariances.
```

也就是：

- ED：严格点对点，对 shift 敏感。
- DTW：允许局部 warping，对局部错位更稳。
- MSM：elastic + edit-based，可能对长度变化更合理。
- SBD：cross-correlation，对全局 shift 更友好。
- IDK：distributional，不依赖逐点对齐，可能对噪声/局部扰动更稳，但可能丢失时序顺序。

Wang 写 Results 的时候，你要帮他检查每个 claim 是否有图表支持。比如不能写：

> IDK is the best method.

除非平均排名、显著性检验、per-dataset 表都支持。更稳妥的 brilliant 结论是：

> No single measure dominates across all conditions; each paradigm performs well under the invariance it encodes.
